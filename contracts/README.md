# Общий wire-контракт SDK

`routes.json` перечисляет 30 операций API с авторизацией по ключу `isk_`.
`fixtures.json` содержит синтетические запросы и ответы для проверки обоих
клиентов. `schema_version: 1` относится к формату этих файлов, а не к версии
установленного сервера. Описание HTTP-семантики: [справочник API](../reference/api.md).

Это проверенный по серверным DTO снимок API от 14 сентября 2026 года. Фикстуры
не получены из пользовательских разговоров, не содержат ключей или реальных
ID и не являются записью работающего production-контура. Необязательные поля
показаны выборочно; неизвестные поля ответа клиент сохраняет.

## routes.json

`operations` — массив с уникальным `id`. Обязательные поля каждой операции:
`id`, `method`, `path`, `scopes`, `description`, `sdk_node`, `sdk_python`.
`scopes` перечисляет совместно необходимые права; `conditional_scopes` добавляет
права в описанных условиях. Каталог не заменяет серверные ACL.

`path` — шаблон: `{conversation_id}` и другие переменные кодируются как один
сегмент, а `{path...}` допускает несколько независимо кодируемых сегментов.
`query` перечисляет имена параметров, не означает их обязательность.
`request_encoding`/`response_encoding` описывают транспорт, если он отличается
от обычного JSON. `delegation: false` обозначает Apps, где сервер отклоняет
непустой `X-Iskra-Run-As`. `runs.wait` — helper над `runs.get`, отдельного
HTTP-маршрута у него нет.

## fixtures.json

Каждый элемент `cases` содержит:

- `id` — уникальное имя сценария; `operation` ссылается на `operations[].id`;
- `method`, `path` — HTTP-метод и конкретный путь без query string;
- `query` — необязательный объект строковых значений, кодируемых URL encoder;
- `request` — JSON-тело либо описанный ниже multipart-дескриптор; отсутствие
  поля означает отсутствие тела;
- `request_headers` — дополнительные заголовки; авторизация задаётся тестовым
  транспортом отдельно;
- `response.status`, `response.headers`, `response.body` — результат;
- необязательные `notes` и `expect` — пояснение и ожидаемое поведение helper-а.

Обычный объект или массив `response.body` сериализуется в JSON. Строка при
`text/event-stream`, `text/*` или бинарном ответе передаётся как точные UTF-8
байты, без JSON-кавычек. `body: null` при `204` означает **нулевую длину тела**, а
`null` внутри JSON-объекта остаётся настоящим JSON null. `errors.proxyHTML`
описывает возможную ошибку прокси, а не серверный DTO.

Для multipart `request` имеет форму:

```json
{
  "multipart": {
    "fields": {"ttl_seconds": "3600"},
    "files": [
      {"field": "file", "filename": "brief.txt", "content_type": "text/plain", "content": "Hello\n"}
    ]
  }
}
```

Это тестовый дескриптор, который адаптер преобразует в `multipart/form-data`,
а не JSON, отправляемый серверу. `content` кодируется UTF-8; повторные
`files` с одинаковым `field` становятся отдельными частями формы. Boundary
создаёт HTTP-библиотека: его буквальное значение контракт не фиксирует.
Содержимое `bundle` в Apps-фикстурах — транспортный маркер, а не архив,
пригодный к публикации. Интеграционный тест Apps должен предоставить валидный
bundle независимо от этих HTTP-фикстур.

SSE хранится непосредственно в строковом `response.body`, включая комментарии,
переводы строк и пустые строки между событиями. Разбивайте UTF-8 байты на
произвольные транспортные чанки: границы чанков не совпадают с событиями или
границами многобайтных символов. Для runs `expect.event_ids` перечисляет SSE
`id`, а `resume_after` равен последнему `id + 1`. Для OpenAI `expect.chunks`
содержит JSON-события, `done: true` требует терминатора `[DONE]`.

## Что проверяют сценарии

Есть пример каждого маршрута и отдельные случаи для различий, которые легко
потерять в клиенте: пустой DELETE, nullable run-поля и pins, отсутствующий
workspace ID, collection reference с нулевым locator, empty/null skills,
частичный ответ `422`, все терминальные статусы, разрыв позиций ленты, SSE
с `id: -1`, три формата ошибок, Apps `approval_required` и два режима OpenAI.
Имена и текст синтетических данных не являются требованиями к продуктовой
формулировке. Проверка метода/пути/сериализации и сохранения ответа важнее
совпадения строк в реализации SDK.
