# Проверка SDK на работающем стеке

`node.mjs` и `python.py` вызывают настоящий API через установленные пакеты.
Они запускаются отдельно от unit-тестов: нужны доступный стек и API-ключи,
а запросы к модели расходуют обычную квоту профиля.

| Сценарий | Что проверяется |
|---|---|
| Каталоги | Defaults, навыки, специалисты, модели и Память читаются по ключу |
| Границы прав | Ключ только с `chat:run` получает 403 при чтении Памяти и загрузке файла |
| Контекст Python | Выбор и освобождение workspace, добавление, смена режима и удаление ссылки на Память |
| Память Python | Создание папки, multipart upload, browse и побайтовое скачивание |
| Асинхронный ход | Файл с уникальным маркером → run → SSE → wait → ответ содержит маркер |
| Повтор и resume | Idempotency-Key возвращает тот же run; terminal доступен при повторном SSE |
| Node chat/OpenAI | Native chat и OpenAI stream завершаются с ожидаемым ответом |
| Node cancel | Явная отмена run приводит к терминальному состоянию |
| Очистка | Созданные разговоры удаляются через SDK даже при ошибке сценария |

Сначала соберите и установите npm tarball и Python wheel по инструкциям
пакетов. Скопируйте `node.mjs` в Node-проект, где установлен SDK. Запустите
оба сценария интерпретаторами этих проектов. Конфигурация передаётся JSON
через stdin (не через аргументы процесса):

```json
{
  "baseUrl": "https://your-iskra.example",
  "apiKey": "isk_FULL_KEY",
  "restrictedApiKey": "isk_CHAT_ONLY_KEY",
  "marker": "SDK_unique_random_marker",
  "directoryId": "optional-writable-memory-directory-uuid"
}
```

Полный ключ требует `chat:run`, `skills:run`, `files:read`, `files:write`,
`memory:read`, `memory:write`. Ограниченный ключ требует только `chat:run`.
`directoryId` — отдельная тестовая папка Памяти с правом записи. Без неё
Python явно отмечает сценарии workspace и записи в Память как `skip`.

Сценарии возвращают JSON с результатами и код выхода 1 при ошибке.
Они не печатают ключи и полные ответы модели. Папка с именем `marker`,
созданная внутри `directoryId`, возвращается в `memory_folders`: удалите
её после проверки через интерфейс Памяти. У bearer API пока нет маршрута
удаления папки. Ключи принадлежат вызывающему приложению; отзывайте временные
ключи после теста.

Для запуска из собственного test runner передайте также `journalPath` —
путь к приватному временному файлу. Сценарии записывают туда NDJSON с ID
созданных разговоров и папок сразу после ответа API. Родительский процесс
может завершить очистку после прерывания сценария; ключи в журнал не попадают.

Unit-тесты отдельно проверяют принудительный обрыв SSE, redirect, deadline,
ошибки proxy, утечки ключей и все 30 HTTP-операций на общих fixtures.
Live-сценарии не создают приложения и новые корневые папки, не включают
raw LLM и не заменяют эти проверки.
